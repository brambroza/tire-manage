# แผนปรับการเพิ่มรถ: กรอกชื่อเรียกหรือทะเบียนอย่างใดอย่างหนึ่งก็ได้

สถานะ: แก้โค้ดและเขียน migration 017 แล้ว (2026-10-28) ยังไม่ได้ apply บนฐานข้อมูลจริง และยังไม่ได้ทดสอบ UI ผ่าน Browser

คำถาม 4 ข้อด้านล่างยังไม่ได้รับคำตอบจากลูกค้า โค้ดจึงทำตามตัวเลือกที่แนะนำทุกข้อ: ไม่มีทะเบียน = ไม่มีจังหวัด, รถไม่มีทะเบียนห้ามชื่อซ้ำในบริษัท, ช่างเพิ่มรถด้วยชื่อเรียกได้, ลบทะเบียนออกจากรถเดิมได้เมื่อมีชื่อเรียก ถ้าลูกค้าเลือกต่างออกไปให้ปรับตามหมายเหตุในแต่ละข้อ

กฎใหม่ที่ต้องการ: รถหนึ่งคันต้องมี **ชื่อเรียกรถ** หรือ **ทะเบียน** อย่างน้อยหนึ่งอย่าง จะมีทั้งสองอย่างก็ได้ แต่ห้ามว่างทั้งคู่ กฎนี้ใช้กับทุกช่องทางที่สร้างหรือแก้รถ

หมายเหตุด้านสัญญา: งานนี้เป็นการเปลี่ยน requirement หลังรอบ nickname (เอกสาร `docs/vehicle-nickname.md` ระบุว่าทะเบียนยังบังคับ) จึงควรออกเป็น Change Request ไม่ใช่ bug

## สิ่งที่พบในโปรเจค

- ฐานข้อมูล: `vehicles.plate_no text not null`, `province text not null`, `unique (company_id, plate_no, province)` ส่วน `nickname` ว่างได้และซ้ำได้ (schema.sql บรรทัด 186–215, migration 016)
- Views `tire_overview` และ `vehicle_change_alerts` ส่ง `plate_no` / `nickname` ผ่านตรง ๆ ไม่มีสูตรที่อาศัยทะเบียน จึงไม่ต้องสร้าง view ใหม่
- จุดสร้าง/แก้รถมี 2 ทาง
  - แอดมิน (รวม super admin ทำแทนลูกค้า): `src/app/(app)/vehicles/vehicle-form.tsx` + `vehicles/actions.ts` (`createVehicle`, `updateVehicle`) ทะเบียนบังคับและต้องตรง `PLATE_PATTERN` สำหรับรถใหม่หรือทะเบียนที่เปลี่ยน
  - ช่างหน้างาน: `src/app/(app)/service/service-wizard.tsx` + `ensureServiceVehicleAction` ใน `service/actions.ts` หาหรือสร้างรถจาก (ทะเบียน + จังหวัด) เท่านั้น ขั้น `plate` บังคับกรอกทะเบียนก่อนไปต่อ
- Type `plate_no: string` ถูกใช้แบบไม่กัน null ใน 6 จุด ซึ่งจะพังทันทีถ้ามีรถไม่มีทะเบียน
  - `service-wizard.tsx` บรรทัด 561–563 (`chooseVehicle` แยกหมวด/เลข) และ 588 (หาทะเบียนซ้ำ)
  - `mileage-client.tsx` บรรทัด 86 (หาทะเบียนซ้ำ)
  - `vehicle-search.tsx` บรรทัด 37–38 (บรรทัดรอง “ทะเบียน · จังหวัด”)
  - `vehicles-client.tsx` บรรทัด 214–219, `vehicles/[id]/page.tsx` บรรทัด 103, `vehicle-form.tsx` บรรทัด 190 (หัว modal)
  - `vehicles-export.ts` บรรทัด 68, 315 ส่งทะเบียนเข้า `escapeHtml` ตรง ๆ
- ตัวช่วยที่รองรับ null อยู่แล้ว: `vehicleLabel`, `matchesVehicle`, `vehicleSearchFilter` ใน `src/lib/vehicle-display.ts` และ `tire-events.ts`, `notifications.ts`, `import-actions.ts` ใช้ `vehicleLabel` เป็นหลัก
- หน้ารายการรถ หน้าเลขไมล์ และรายงาน fleet เรียง `.order('plate_no')` รถไม่มีทะเบียนจะไปอยู่ท้ายสุดรวมกัน
- ตามบันทึกเดิม migration 016 ยังไม่ได้ apply บน production จึงรวมรอบ apply กับ 017 ได้

## คำถามที่ต้องยืนยันก่อนเริ่มทำ

1. **จังหวัดของรถที่ไม่มีทะเบียน** แนะนำให้เว้นว่าง (จังหวัดเป็นส่วนหนึ่งของทะเบียน ไม่มีทะเบียนก็ไม่มีจังหวัด) ทางเลือกคือยังบังคับเลือกจังหวัดเสมอ ซึ่งจะได้ค่าเริ่มต้นกรุงเทพมหานครปนอยู่ในข้อมูลโดยไม่มีความหมาย แผนนี้เขียนตามข้อแนะนำ
2. **ชื่อซ้ำของรถที่ไม่มีทะเบียน** แนะนำให้ห้ามซ้ำภายในบริษัท (ไม่สนตัวพิมพ์เล็ก–ใหญ่) เพราะไม่มีทะเบียนไว้แยกคัน ส่วนรถที่มีทะเบียนยังตั้งชื่อซ้ำกันได้ตามกฎเดิม
3. **ช่องทางช่าง** ให้ช่างสร้างรถด้วยชื่อเรียกอย่างเดียวได้ด้วยหรือเฉพาะแอดมิน แผนนี้รองรับทั้งสองทางเพราะช่างสร้างรถใหม่หน้างานได้อยู่แล้ว ถ้าลูกค้าต้องการจำกัดเฉพาะแอดมินให้ตัดข้อ 5 ออก
4. **การลบทะเบียนออกจากรถเดิม** อนุญาตเมื่อรถมีชื่อเรียกแล้ว ประวัติยางยังผูกกับรหัสรถเดิม ถ้าลูกค้าไม่ต้องการให้ลบทะเบียนทิ้ง ให้ล็อกช่องทะเบียนในโหมดแก้ไขเมื่อมีค่าอยู่แล้ว

## แผนงาน

### 1. ฐานข้อมูล (migration 017)

ไฟล์ `supabase/migrations/017_vehicle_plate_optional.sql` ทำใน transaction เดียว รันซ้ำได้ และปรับ `supabase/schema.sql` ให้ตรงกันสำหรับฐานข้อมูลใหม่

- `alter table public.vehicles alter column plate_no drop not null`
- `alter table public.vehicles alter column province drop not null`
- เพิ่ม `check` ชื่อ `vehicles_identity_check`: ต้องมี `nickname` หรือ `plate_no` อย่างน้อยหนึ่งค่าที่ไม่ว่าง และ `province` ต้องมีก็ต่อเมื่อมี `plate_no` (ทั้งคู่มีหรือทั้งคู่ว่าง) ใช้ `btrim(...) <> ''` กันค่าช่องว่างล้วน
- เพิ่ม partial unique index `vehicles_nickname_only_unique on (company_id, lower(btrim(nickname))) where plate_no is null` ตามคำถามข้อ 2
- `unique (company_id, plate_no, province)` เดิมคงไว้ ค่า null ไม่ชนกันอยู่แล้ว
- ไม่ต้องแก้ view ทั้งสองตัว เพราะคอลัมน์ยังเป็น `text` เหมือนเดิม
- ข้อมูลเดิมทุกแถวมีทะเบียนครบ จึงไม่มี backfill และ `check` ใหม่ผ่านทันที
- เพิ่ม `supabase/scripts/verify_017.sql` อ่านอย่างเดียว ตรวจ nullable ของสองคอลัมน์ constraint และ index

ข้อควรระวังเหมือน 016: `ALTER TABLE` ล็อกตารางรถช่วงสั้น และเพิ่ม `check` จะสแกนทั้งตาราง รันช่วงที่หยุดบันทึกงานได้ ตรวจ backup ก่อน

### 2. กฎตรวจค่ากลาง (`src/lib/vehicle-schema.ts`)

สร้าง schema ที่ใช้ร่วมกันทั้งฟอร์มแอดมินและหน้าช่าง แทนที่กฎทะเบียนที่กระจายอยู่ใน `vehicles/actions.ts` และ `service/actions.ts`

- `plate_no`: trim, ค่าว่างเป็น `null`, ยาวไม่เกิน 20
- `province`: trim, ค่าว่างเป็น `null`
- `refine` ระดับ object
  - ไม่มีทั้ง `nickname` และ `plate_no` แจ้งที่ช่องทะเบียน “กรุณากรอกทะเบียนหรือชื่อเรียกรถอย่างน้อยหนึ่งอย่าง”
  - มีทะเบียนแต่ไม่มีจังหวัด แจ้ง “กรุณาเลือกจังหวัด”
  - ไม่มีทะเบียน ให้บังคับ `province` เป็น `null` ใน transform เพื่อไม่ให้ค่าเริ่มต้นจากฟอร์มหลุดลงฐานข้อมูล
- กฎ `PLATE_PATTERN` ยังใช้กับทะเบียนใหม่หรือทะเบียนที่เปลี่ยนเท่านั้น (ข้อยกเว้นทะเบียนเก่าที่บันทึกก่อนกฎยังคงไว้)
- ส่งออก `VEHICLE_IDENTITY_MESSAGE` เพื่อใช้ข้อความเดียวกันทั้งฝั่ง client และ server

### 3. Server actions ของแอดมิน (`vehicles/actions.ts`)

- `vehicleSchema` / `newVehicleSchema` เปลี่ยนไปใช้ schema กลางจากข้อ 2
- `updateVehicle` ตรวจรูปแบบทะเบียนเฉพาะเมื่อค่าใหม่ไม่ว่างและต่างจากเดิม และคงกฎเดิมเรื่องประเภทเพลาและสาขา
- จับ error `23505` แยกสองกรณี: ทะเบียน+จังหวัดซ้ำ และชื่อเรียกซ้ำของรถที่ไม่มีทะเบียน แล้วส่ง `fieldErrors` ไปที่ช่องที่ถูกต้อง
- `revalidateVehicle` ไม่ต้องเปลี่ยน

### 4. ฟอร์มแอดมิน (`vehicle-form.tsx`)

- ช่องทะเบียนเอาป้าย “จำเป็น” ออก เปลี่ยน hint เป็น “กรอกทะเบียนหรือชื่อเรียกรถอย่างน้อยหนึ่งอย่าง” และแสดงป้ายเดียวกันที่ช่องชื่อเรียก
- ช่องจังหวัดแสดงและบังคับเฉพาะเมื่อกรอกทะเบียน (ช่องใดช่องหนึ่งของหมวด/เลขมีค่า) เมื่อลบทะเบียนออกให้ล้างจังหวัดด้วย
- ตรวจฝั่ง client ก่อนส่ง: ว่างทั้งคู่ให้แจ้งข้อผิดพลาดทันทีโดยไม่เรียก server
- หัว modal โหมดแก้ไขใช้ `vehicleLabel(vehicle)` แทน `${plate_no} ${province}`
- โหมดแก้ไข: ถ้าผู้ใช้ลบทะเบียนออกจากรถที่เคยมีทะเบียน แสดงคำเตือนสั้น ๆ ว่ารถจะเหลือเฉพาะชื่อเรียก (ตามคำถามข้อ 4)

### 5. หน้าช่าง (`service-wizard.tsx` + `ensureServiceVehicleAction`)

- ขั้น `plate` เพิ่มทางเลือกที่สาม ใต้ช่องทะเบียน: “ไม่มีทะเบียน เพิ่มรถด้วยชื่อเรียก” เปิดช่องชื่อเรียกและปุ่มตกลงแยก ช่องทะเบียนกับช่องชื่อเรียกใช้คนละปุ่ม เพื่อไม่ให้ช่างสับสนว่าต้องกรอกทั้งคู่
- `submitPlate` คงเดิมสำหรับทะเบียน เพิ่ม `submitNickname`: ตัดช่องว่าง ตรวจว่าไม่ว่าง เทียบกับรถที่ไม่มีทะเบียนในรายการ (ไม่สนตัวพิมพ์เล็ก–ใหญ่) ถ้าพบให้เลือกคันนั้นทันที ไม่สร้างซ้ำ ถ้าไม่พบตั้ง `isNewVehicle` แล้วไปขั้น `category`
- ขั้น `category` ซ่อนช่อง “จังหวัดของทะเบียน” เมื่อไม่มีทะเบียน และเปลี่ยนข้อความหัวเป็น “ชื่อเรียก X ยังไม่มีในระบบ”
- `chooseVehicle` รองรับ `plate_no` เป็น null (ตั้งหมวด/เลขเป็นค่าว่าง) และสรุปด้านบนใช้ `vehicleLabel`
- `serviceVehicleSchema` ใช้ schema กลางจากข้อ 2 รวมกับ `vehicle_id`
- `ensureServiceVehicleAction` หารถจาก `vehicle_id` ก่อน ถ้าไม่มีและมีทะเบียนใช้ (ทะเบียน + จังหวัด) ถ้าไม่มีทะเบียนใช้ `plate_no is null and lower(nickname) = lower(input)` ใน insert ส่ง `province: null` เมื่อไม่มีทะเบียน และแยกข้อความ `23505` สองแบบเช่นเดียวกับข้อ 3
- `ServiceVehicleResult` และ `VehicleLite` เปลี่ยน `plate_no`, `province` เป็น `string | null`

### 6. รายการ ค้นหา รายงาน และส่งออก

- `src/lib/database.types.ts`: `vehicles.plate_no`, `vehicles.province` เป็น `string | null` รวมถึง type ของ view และ type ที่ประกาศซ้ำใน `tire-events.ts`, `dashboard/page.tsx`, `fleet-report.ts`, `mileage-client.tsx`, `notifications.ts` แล้วใช้ `npx tsc --noEmit` ไล่จุดที่เหลือ
- `vehicle-search.tsx`: บรรทัดรองแสดง “ทะเบียน · จังหวัด” เมื่อมีทะเบียน ไม่เช่นนั้นแสดง “ไม่มีทะเบียน” เพื่อให้แยกจากรถชื่อซ้ำที่มีทะเบียนได้
- `vehicles-client.tsx`, `vehicles/[id]/page.tsx`: แสดง “-” หรือ “ไม่มีทะเบียน” แทนค่าว่าง
- `mileage-client.tsx` บรรทัด 86 และ `service-wizard.tsx` บรรทัด 588: ข้ามรถที่ `plate_no` เป็น null ในการหาทะเบียนซ้ำ
- การเรียงลำดับ: `vehicles/page.tsx`, `mileage/page.tsx`, `reports/fleet/page.tsx` เปลี่ยนเป็น `.order('plate_no', { nullsFirst: false }).order('nickname')` หรือเรียงฝั่ง server ด้วย `vehicleLabel` เพื่อให้รถไม่มีทะเบียนไม่กองรวมกันโดยไม่มีลำดับ
- `vehicles-export.ts`: `plateNo: v.plate_no ?? ''` และคอลัมน์ทะเบียนใน Excel/PDF แสดง “-” เมื่อว่าง จังหวัดแสดง “-” อยู่แล้ว
- รายงาน การแจ้งเตือน และประวัติยางที่ใช้ `vehicleLabel` อยู่แล้วไม่ต้องแก้ ตรวจซ้ำด้วย `tsc`

### 8. นำขึ้นใช้งาน

## สิ่งที่ทำแล้ว (2026-10-28)

- `supabase/migrations/017_vehicle_plate_optional.sql` และ `supabase/scripts/verify_017.sql`; `supabase/schema.sql` ปรับให้ตรงกันสำหรับฐานข้อมูลใหม่

- ฟอร์มแอดมิน: ทะเบียนไม่บังคับ จังหวัดแสดงเฉพาะเมื่อกรอกทะเบียน เตือนเมื่อลบทะเบียนออกจากรถเดิม ตรวจฝั่ง client ก่อนส่ง
- หน้าช่าง: ปุ่ม “เพิ่มด้วยชื่อเรียก” ใต้ช่องทะเบียน ถ้าชื่อตรงกับรถไม่มีทะเบียนคันเดิมจะเลือกคันนั้นให้แทนการสร้างซ้ำ ขั้นประเภทรถซ่อนช่องจังหวัดและชื่อเรียกเมื่อไม่มีทะเบียน
- `ensureServiceVehicleAction` หารถจาก `vehicle_id` / ทะเบียน+จังหวัด / ชื่อเรียก (ilike แบบ escape) และแปลง unique violation เป็นข้อความแยกสองกรณี
- Type `plate_no` และ `province` เป็น `string | null` ทั้งระบบ รายการ ค้นหา รายละเอียด ส่งออก และหน้าเลขไมล์แสดง “ไม่มีทะเบียน” หรือ “-” แทนค่าว่าง การเรียงลำดับใช้ `nullsFirst: false` แล้วตามด้วยชื่อเรียก
- `scripts/vehicle-identity.test.mjs` 6 กรณี (รวมกับชุดเดิม 12 กรณีผ่าน) รันด้วย `node --test scripts/vehicle-identity.test.mjs scripts/vehicle-nickname.test.mjs`

ผลตรวจ: `npx tsc --noEmit` ผ่าน, `npm run lint` ไม่มี error (warning เดิม 7 จุด), `npm run build -- --webpack` ผ่าน

ทดสอบฐานข้อมูลบน PostgreSQL 16 ชั่วคราว: schema ที่ commit ล่าสุด → 016 → 017 → 017 ซ้ำ ผ่าน; `verify_017.sql` คืนค่าตามคาด; schema.sql ใหม่สร้างฐานข้อมูลสดได้; constraint ปฏิเสธรถที่ไม่มีทั้งทะเบียนและชื่อ ทะเบียนช่องว่าง ทะเบียนไม่มีจังหวัด ชื่อเรียก+จังหวัดโดยไม่มีทะเบียน และชื่อซ้ำของรถไม่มีทะเบียนในบริษัทเดียวกัน (ไม่สนตัวพิมพ์และช่องว่าง); ยอมรับชื่อซ้ำต่างบริษัทและชื่อซ้ำเมื่อมีทะเบียน; views ทั้งสองยังคง `security_invoker=true`
