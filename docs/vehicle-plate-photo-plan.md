# แผนเพิ่มรถจากภาพป้ายทะเบียนและเก็บไฟล์แนบ

สถานะ: แผนงาน ยังไม่ได้เพิ่มฟีเจอร์ รัน migration หรือส่งภาพไปบริการ OCR

ขอบเขตที่ผู้ใช้ยืนยัน: **ภาพป้ายทะเบียนรถ** อ่านเลขทะเบียนและจังหวัด ไม่ใช่ภาพเล่มทะเบียนหรือเอกสารจดทะเบียน

## สิ่งที่พบในโปรเจค

- เพิ่ม/แก้รถผ่าน `src/app/(app)/vehicles/vehicle-form.tsx` และ `vehicles/actions.ts` ทั้งแอดมินบริษัทและ super admin
- ช่างสร้างรถใหม่ได้ผ่าน `service/service-wizard.tsx` และ `ensureServiceVehicleAction` จึงต้องรองรับช่องทางนี้ด้วย
- `src/lib/tire-images.ts` เก็บรูปยางใน bucket สาธารณะ `tire-images` จึงนำรูปป้ายทะเบียนไปใช้ร่วมโดยตรงไม่ได้ตามสิทธิ์ที่วางแผนไว้
- ยังไม่มีตัวอ่านภาพ OCR; หน้า scan ที่มีเป็นการรับข้อความซีรีย์จากเครื่องสแกนหรือคีย์บอร์ด
- ทะเบียนปัจจุบันจำกัดหมวด 1–2 ตัวและเลข 1–4 หลัก ต้องเก็บผลอ่านต้นฉบับและแจ้งเมื่อรูปแบบไม่รองรับ ห้ามตัดตัวอักษรให้ผ่านกฎอัตโนมัติ หากต้องรองรับหมวดอื่นต้องปรับกฎร่วมกันทุกช่องทางก่อนเปิดใช้
- ฟอร์มใหม่ตั้งจังหวัดเริ่มต้นเป็นกรุงเทพมหานคร เมื่ออ่านภาพแล้วไม่พบจังหวัดต้องแสดงว่ายังไม่ทราบ และให้เลือกเอง ห้ามถือว่าค่าเริ่มต้นคือผลจากภาพ
- Server Actions จำกัด body 4 MB จึงเลือกอัปโหลดไฟล์ตรงเข้า Storage ผ่านสิทธิ์ชั่วคราว ไม่เพิ่มขนาด request ของทุก action

## ประสบการณ์ใช้งาน

1. เข้า **เพิ่มรถ → ถ่ายภาพป้ายทะเบียน / เลือกรูปจากเครื่อง** การแนบรูปเป็นทางเลือก ผู้ใช้ยังพิมพ์ข้อมูลตามเดิมได้
2. แสดงตัวอย่างภาพ ผู้ใช้หมุนหรือครอปบริเวณป้ายได้ อัปโหลดภาพต้นฉบับเข้า private storage และใช้ภาพที่เตรียมสำหรับ OCR แยกต่างหาก
3. เริ่มอ่านข้อความอัตโนมัติหลังอัปโหลดสำเร็จ แสดงสถานะ “กำลังอ่านทะเบียน…” ไม่ต้องกดอ่านซ้ำทุกครั้ง
4. เติมหมวดทะเบียน เลขทะเบียน และจังหวัดที่อ่านได้ พร้อมป้าย “อ่านจากภาพ · กรุณาตรวจสอบ” ถ้าไม่พบ/ไม่แน่ชัด ให้กรอกหรือเลือกเอง ไม่มีการเดาจังหวัดหรือแก้ตัวอักษรที่กำกวมเงียบ ๆ
5. ผู้ใช้ตรวจเทียบรูปกับค่าที่เติม แก้ไขได้ และกรอกชื่อเรียก ประเภทเพลา และข้อมูลอื่นตามปกติ
6. กดบันทึก ระบบตรวจทะเบียน + จังหวัดซ้ำภายในบริษัท บันทึกรถและผูกไฟล์แนบ เมื่อเสร็จจึงแจ้งว่าบันทึกครบแล้ว
7. รายละเอียดรถมีส่วน **ภาพป้ายทะเบียน** เปิดดู/ดาวน์โหลดภาพต้นฉบับ และแนบภาพเพิ่มได้ แสดงผู้แนบและวันเวลา แถวรายการรถใช้ไอคอนจำนวนไฟล์โดยไม่โหลดภาพเต็มทุกแถว

ขอบเขตเริ่มต้น: แนบครั้งละหนึ่งภาพเป็นแหล่งอ่าน OCR ต่อการเพิ่มรถหนึ่งคัน รองรับแนบภาพเพิ่มภายหลัง ภาพใหม่ไม่ลบภาพเดิมหรือเปลี่ยนทะเบียนของรถเดิมโดยอัตโนมัติ

## การอ่านทะเบียน

- สร้างตัวเชื่อม OCR แยกจากฟอร์ม เช่น `src/lib/vehicle-plate-ocr.ts` เพื่อเปลี่ยนผู้ให้บริการได้โดยไม่เปลี่ยนขั้นตอนใช้งาน
- ผู้ให้บริการเริ่มทดลอง: Google Cloud Vision ซึ่งมี Thai (`th`) ในรายการภาษาที่รองรับ แต่ต้องทดลองกับรูปป้ายจริงก่อนสรุปความแม่นยำ
- ผลภายในประกอบด้วย `plate_prefix`, `plate_number`, `province`, ข้อความที่อ่านจากบริเวณป้าย และสถานะตรวจทานแต่ละช่อง ไม่สร้างเปอร์เซ็นต์ความมั่นใจขึ้นเอง ถ้าผู้ให้บริการไม่มีคะแนนที่ใช้ได้ให้ใช้สถานะอ่านได้/ต้องตรวจ/อ่านไม่สำเร็จ
- แยกเลขทะเบียนออกจากข้อความอื่นบนป้าย เช่น ตัวเลขส่วนหัว ไม่หยิบชุดตัวเลขแรกมาใช้ทันที
- เทียบจังหวัดกับ `src/lib/provinces.ts`; ผลใกล้เคียงแสดงเป็นตัวเลือก ไม่ยืนยันแทนผู้ใช้
- ถ้าพบหลายป้าย ให้ผู้ใช้เลือกบริเวณหรือถ่ายใหม่ ไม่เลือกป้ายใดป้ายหนึ่งเงียบ ๆ
- ไม่อนุมานชื่อเรียก ยี่ห้อ รุ่น หรือประเภทเพลาจากป้ายทะเบียน
- เมื่อผู้ใช้แก้ค่าหรือเปลี่ยนรูปขณะอ่านอยู่ ผลตอบกลับเก่าต้องไม่ทับค่าปัจจุบัน ใช้รหัสคำขอและติดตามช่องที่ผู้ใช้แก้แล้ว
- OCR ล่ม/หมดเวลา: แสดงข้อผิดพลาดให้ลองใหม่หรือกรอกเองได้ ภาพที่อัปโหลดสำเร็จยังแนบกับรถได้
- จำกัดการเรียกต่อผู้ใช้/บริษัท และใช้ผลเดิมสำหรับไฟล์เดิมภายในบริษัท เพื่อลดการคิดค่าบริการซ้ำ ติดตามจำนวนคำขอ เวลาอ่าน และต้นทุนก่อนกำหนดงบจริง

## ไฟล์แนบและสิทธิ์

เสนอ bucket ใหม่ `vehicle-attachments` แบบ **private** จัด object path จากรหัสที่ server สร้าง เช่น `<company_id>/<attachment_id>/original.jpg` ไม่ใช้ทะเบียนหรือชื่อไฟล์ผู้ใช้เป็น path

เสนอ table ใหม่ `vehicle_attachments`:

| กลุ่ม | ข้อมูลหลัก |
|---|---|
| ตัวตน | `id`, `company_id`, `vehicle_id` (ว่างได้ระหว่างรอผูกกับรถ) |
| ไฟล์ | `storage_path`, `original_filename`, `mime_type`, `size_bytes`, `sha256` |
| สถานะ | `pending`, `uploaded`, `attached`, `deleting` พร้อมเวลาหมดอายุไฟล์ชั่วคราว |
| การอ่าน | `ocr_status`, ผลที่อ่านจากป้าย, provider/version, เวลาอ่าน |
| ตรวจสอบย้อนหลัง | `uploaded_by`, `created_at`, `attached_at` |

- แอดมินแนบและแก้ไขของบริษัทตัวเอง; super admin ต้องเลือกบริษัทเป้าหมาย; ช่างแนบระหว่างสร้างรถในหน้าช่างของบริษัทตัวเอง
- ช่างดูภาพรถของบริษัทได้ตามสิทธิ์เข้าถึงรถเดิม การลบไฟล์ให้แอดมินบริษัทและ super admin
- ตรวจสิทธิ์ทั้ง metadata และ Storage RLS และตรวจว่ารถกับไฟล์เป็นของบริษัทเดียวกันตอนผูก ห้ามเชื่อ `company_id`, object path หรือผล OCR จาก browser โดยตรง
- เปิดภาพผ่าน URL อายุสั้นหลังตรวจสิทธิ์ เก็บเฉพาะ object path ในฐานข้อมูล ไม่บันทึก signed URL ที่หมดอายุได้
- เก็บภาพต้นฉบับไว้เป็นไฟล์แนบ ส่วนรูปย่อ/ภาพครอปสำหรับอ่าน OCR เป็นไฟล์อนุพันธ์ เก็บชนิดและเส้นทางแยกกัน
- ค่าเริ่มต้นที่เสนอ: ภาพต้นฉบับไม่เกิน 10 MB, JPG/PNG/WebP ตรวจชนิดจากเนื้อหาไฟล์และขนาดภาพจริงฝั่ง server รวมถึงจำกัดจำนวนพิกเซล ภาพ HEIC จาก iPhone ให้รองรับการแปลงเป็น JPEG สำหรับ OCR หลังทดสอบตัวแปลงในสภาพแวดล้อม deploy โดยยังเก็บต้นฉบับ หากยังรองรับไม่ได้ต้องแจ้งก่อนอัปโหลดและแนะนำ JPG ไม่ปล่อยให้ OCR ล้มเหลวภายหลัง
- บอกในจุดแนบรูปว่าภาพจะถูกประมวลผลด้วยบริการอ่านทะเบียนภายนอก เก็บ API credentials ฝั่ง server และไม่เขียนภาพ/base64 หรือ signed URL ลง log

## บันทึกรถกับไฟล์ให้สอดคล้องกัน

Storage และ PostgreSQL ไม่ใช่ transaction เดียวกัน จึงไม่ออกแบบโดยสมมติว่าบันทึกรถและ upload จะ rollback พร้อมกัน:

1. Server ตรวจ session/company scope สร้าง attachment ชั่วคราวและสิทธิ์อัปโหลดเฉพาะ path ที่กำหนด
2. อัปโหลดเข้า Storage จาก browser แล้ว server ตรวจ object จริงก่อนอนุญาต OCR หรือผูกกับรถ
3. ตอนบันทึก ใช้ database transaction สำหรับสร้างรถและผูก attachment ที่ผ่านการตรวจแล้ว ตรวจสิทธิ์ซ้ำและใช้ idempotency key กันกดซ้ำ/การ retry
4. ถ้าทะเบียนซ้ำ แสดงรถเดิมให้ผู้ใช้เลือกว่าจะเปิดดูหรือแนบภาพกับรถนั้น ห้ามเปลี่ยนทะเบียน/ชื่อเรียกรถเดิมหรือสร้างรถซ้ำอัตโนมัติ
5. ถ้าบันทึกล้มเหลว ให้ retry ด้วยไฟล์เดิมได้ ไม่อัปโหลดซ้ำทุกครั้ง
6. ไฟล์ชั่วคราวที่ยกเลิกหรือไม่เคยผูก ล้างตามรอบหลังหมดอายุ (เสนอ 24 ชั่วโมง) งานล้างตรวจสถานะซ้ำและประสานกับการผูกไฟล์เพื่อไม่ลบไฟล์ที่กำลังบันทึก
7. การลบไฟล์ใช้สถานะรอลบและ retry จนลบจาก Storage สำเร็จ ก่อนลบ metadata ไม่ทำให้มีไฟล์ค้างที่ติดตามไม่ได้

## ลำดับพัฒนา

| ช่วง | งาน | ผลที่ตรวจรับได้ |
|---|---|---|
| 1 | ทดลอง OCR กับภาพจริงที่ได้รับอนุญาต 30–50 ภาพ ทั้งชัด เอียง แสงสะท้อน กลางคืน และหลายรูปแบบทะเบียน | รายงานความถูกต้องของทะเบียน/จังหวัดแยกกัน เวลาอ่าน และรูปที่ต้องแก้มือ ก่อนเลือก provider ถาวร |
| 2 | Migration เพิ่ม table/bucket/policies, flow upload–attach–cleanup, ดู/ดาวน์โหลด/ลบ | กรอกข้อมูลเองและเก็บไฟล์แนบได้ครบ โดยยังไม่เปิด OCR |
| 3 | เชื่อม OCR กับฟอร์มแอดมินและ super admin, ตรวจแก้/ตรวจซ้ำ/การ retry | อ่านทะเบียนกับจังหวัด เติมฟอร์มและบันทึกรถพร้อมภาพได้ |
| 4 | ใช้ uploader/OCR ชุดเดียวกันในหน้าช่าง และทดสอบการใช้งานบนมือถือ | ถ่ายรูปแล้วสร้างรถจากงานถอด–ใส่ยางได้ โดยสิทธิ์และการตรวจข้อมูลเหมือนช่องทางหลัก |
| 5 | เปิดให้บริษัททดลองก่อน แล้วเปิดใช้งานทั่วไป | ตรวจสิทธิ์ ไฟล์ค้าง ค่าใช้จ่าย และความถูกต้องของข้อมูลจริง |

## Migration และระบบเดิม

- สร้าง migration ถัดจากลำดับที่มีอยู่ขณะเริ่มพัฒนา แยกจาก migration ชื่อเรียกรถ
- เพิ่ม table, bucket และสิทธิ์ใหม่ ไม่บังคับรถเดิมต้องมีไฟล์แนบ ไม่แก้ประวัติยางหรือเปลี่ยน UUID รถ
- ไม่เปลี่ยน bucket รูปยางจาก public เป็น private เพราะจะกระทบรูปที่ใช้อยู่
- ตรวจข้อจำกัดและระยะเวลาล็อกของ DDL/FK บน staging ก่อนรันจริง ไม่รับรอง zero downtime จากรูปแบบ schema อย่างเดียว
- ลำดับเปิดใช้: migration → ตรวจสิทธิ์และ file lifecycle → deploy โดยปิด feature flag → เปิดให้บริษัททดลอง → เปิดทั่วไป
- ถ้า OCR มีปัญหา ปิด OCR ได้โดยผู้ใช้ยังกรอกทะเบียนและเก็บไฟล์แนบได้ ถ้าฟีเจอร์แนบภาพมีปัญหา ให้กลับไปใช้ flow เพิ่มรถเดิมได้ โดยคงไฟล์ที่บันทึกแล้วไว้

## เกณฑ์ตรวจรับ

- รูปชัดอ่านทะเบียนและจังหวัดได้ และให้แก้ก่อนบันทึกเสมอ; รูปเบลอ/ข้อมูลกำกวม/หลายป้ายไม่เติมข้อมูลที่เดาเป็นค่าที่ผ่านการยืนยัน
- รูปที่ไม่มีจังหวัดไม่บันทึกกรุงเทพฯ จากค่าเริ่มต้นโดยไม่ได้เลือก
- ตัวเลขศูนย์นำหน้าและอักขระไทยคงครบ; รูปแบบที่ระบบยังไม่รองรับไม่ถูกตัดทอน
- เปลี่ยนภาพระหว่าง OCR หรือแก้ช่องด้วยมือ ผลตอบกลับเก่าไม่ทับข้อมูลใหม่
- ชื่อเรียกรถเดิมไม่ถูกแทนด้วยทะเบียนที่ OCR อ่านได้
- ทะเบียนซ้ำต่างจังหวัดแยกได้; ทะเบียนและจังหวัดซ้ำบริษัทเดียวกันไม่สร้างซ้ำ แม้กดบันทึกซ้ำหรือ retry
- แนบรูปแล้วเปิดดู/ดาวน์โหลดต้นฉบับจากรถคันเดิมได้หลัง refresh; URL หมดอายุขอใหม่ได้ตามสิทธิ์
- ผู้ใช้ต่างบริษัทอ่าน ดาวน์โหลด ผูกไฟล์ ลบไฟล์ หรือขอ signed URL ของกันและกันไม่ได้ แม้รู้ attachment UUID/path
- ครอบคลุมไฟล์ปลอม ไฟล์ใหญ่ รูปเสีย เน็ตหลุด ยกเลิกฟอร์ม บันทึกไม่สำเร็จ OCR timeout และงานล้างไฟล์ชั่วคราวชนกับการบันทึก
- ทดสอบ desktop, Android และ iPhone รวมถึงแหล่งภาพกล้อง/คลังรูป; การสร้างรถเดิมแบบไม่แนบไฟล์ยังใช้งานได้

## แหล่งอ้างอิง

- Google Cloud Vision: Thai (`th`) ใน [OCR language support](https://docs.cloud.google.com/vision/docs/languages) และ [การอ่านข้อความจากภาพ](https://docs.cloud.google.com/vision/docs/ocr)
- Supabase: [Private buckets และ RLS](https://supabase.com/docs/guides/storage/buckets/fundamentals), [การเปิดไฟล์ด้วย authenticated download หรือ signed URL](https://supabase.com/docs/guides/storage/serving/downloads)

การรองรับภาษาไทยไม่ใช่หลักฐานความแม่นยำของป้ายทะเบียนชุดใช้งานจริง ต้องวัดจากช่วงทดลองก่อนเสนอค่าความแม่นยำหรือต้นทุนต่อเดือน
